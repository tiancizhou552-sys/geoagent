# 数据说明与已知问题

本文件记录 GeoAgent 所用空间数据的来源、口径与**已发现的问题**。
面试时如果被追问"你的数据质量怎么样"，答案应该来自这里，而不是临场编。

## 四、⚠️ 已发现的数据问题（4 项）

### 1. 停车要素完全没有可用标识

```
parking.geojson      Id 字段 133/133 全部为 0，name 字段 133/133 全部为 null
tempparking.geojson  Id 字段 51/51 全部为 0
```

**影响**：无法用 `Id` 作为唯一键；无法向用户报出"XX 停车场"这类名称。
**处置**：由工具层按要素顺序生成内部 ID（如 `PK-0001`），并在返回结果中附**最近 POI 名称**作为可读定位（例如"图书馆东南侧可停区"）。

### 2. 禁停区有 153 个"洞"，判定顺序其实不影响结果（一次被推翻的初判）

`noparking` 是 MultiPolygon，**2 个部件、合计 4.41 km²**，占研究区 64%。
它的语义是「校园范围扣除各停车区」的兜底面，而不是若干独立的禁停地点。

第一版核查用**质心**做测试，得到「8 个可停区被判成禁停」，据此判断原系统的判定顺序有缺陷。
**重新核查后该结论被推翻：**

| 测试点取法 | 旧顺序（禁停优先） | 新顺序（可停优先） |
|---|---|---|
| `centroid` 质心 | 误判 8 / 133 | 误判 7 / 133 |
| `representative_point` 内部点 | **误判 0 / 133** | **误判 0 / 133** |

原因有两层：
1. `noparking` 的第二个部件带 **153 个内环（洞）**，这些洞正是被挖掉的停车区 —— 禁停区并不覆盖停车区；
2. 133 个可停区里有 **8 个的质心落在自身多边形之外**（凹多边形 / 多部件），
   所以质心法测出的是**假阳性**。

**结论**：原系统的判定顺序**没有实际缺陷**，不需要修。
本项目仍将优先级定为 **可停区 > 可暂停区 > 禁停区**，但这是**防御性设计**
（语义上"明确可停优先于兜底禁停"更好推理；若将来洞的拓扑被改坏，也会优雅降级），
而**不是在修一个不存在的 bug**。

> **这条值得记住**：验证空间数据时不要用质心，要用 `representative_point()`。
> 质心不保证落在多边形内部 —— 凹多边形和多部件几何上经常落在外面。

### 3. 原系统 `check_zone` 的名称回退逻辑确实失效

```python
props.get("name", props.get("Id", f"区域-{i}"))
```

Python 的 `dict.get(k, default)` 在**键存在但值为 `None`** 时返回 `None`，不会走默认值。
实测：第一个可停区的属性是 `{'Id': 0, 'name': None, ...}`，`'name' in props` 为 `True`，
上述表达式返回 `None`，**恒不回退**。

**处置**：新工具层不继承这段逻辑，统一用显式生成的内部 ID + 最近 POI 名称做可读定位。

### 4. 原系统路网图每次请求重建

`build_road_graph()` 在每次 `/api/navigate` 调用时重新解析 452 条线、构建 1931 条边。

**影响**：单次约几十毫秒，不致命，但纯属浪费。
**处置**：启动时构建一次并缓存为模块级单例；图在进程内只读。
另外把最近节点查找从 O(n) Python 循环改为 NumPy 向量化（1636 个节点）。

### 抓取口径（踩过的坑，写下来防复发）

1. **泛词抓不全，必须逐个点名。** 腾讯关键词搜索按相关度排序、单关键词实测只回 ≤60 条。
   `"教学楼"` 泛词只回 1 条；必须写成 `"第四教学楼"`（→6 条，含 A区/B座/C区/B区）才拿得到。
   宿舍同理：`"宿舍"`/`"公寓"` 只回「荟园大学生公寓区」这种整块区域，
   必须按苑区点名 `"华中农业大学荟园"`（→荟园 1~21 栋）、`"…北苑"`（→北苑 1~15 栋）等，
   南苑/博园/宝积苑/西苑逐栋才都能抓全。
2. **边界做两级过滤，零缓冲。** 请求时用 `boundary=rectangle(lat,lng,lat,lng)`（**西南角在前**）
   拿校园外接矩形粗筛；拿到结果后逐点 `gcj02_to_wgs84()` 转 WGS84，再用
   `campus_boundary.geojson` 做 `polygon.contains(Point(lon,lat))` 精筛。**不设 buffer**。
3. **腾讯返回 GCJ-02，必须转 WGS84 才能进数据层。** 实测偏移约 590 m（详见 `gis/gcj.py` 说明）。
   原始文件里 `lat_wgs/lng_wgs` 是转换值，`lat_gcj/lng_gcj` 保留腾讯原值以便回溯。
4. **停车类不进 POI 层。** 腾讯返回大量「XX地上/地下停车场」重名批次（「内部地面停车场」一次 12 条同名），
   且名字带「楼」会被误判成「学院与科研」。停车/禁停已由 `parking.geojson`/`noparking.geojson` 独立成层，
   builder 里用 `PARKING_SUBSTR` 一律剔除。
5. **每日调用量有上限。** 实测关键词超过约 50 个后会返回 `status=121 此key每日调用量已达到上限`，
   当日后续关键词静默失败（≠key 坏了，次日自动恢复）。所以关键词表要精挑，别拿泛词凑数。
